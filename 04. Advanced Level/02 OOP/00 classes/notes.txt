```python
"""
# ========================= Python Class Working Flow with Heap Memory =========================

Python Class Working Flow — Step by Step
=========================================

Important Note:
---------------

Python's memory model should not be treated exactly like
C/C++ "Stack Memory and Heap Memory".

In CPython:

- Python objects are generally allocated in heap-managed memory.
- Local variables generally hold references to objects.
- An execution frame is created when a function is called.
- Memory management can vary depending on the Python implementation.

Therefore, the terms Stack/Heap are used below mainly
to make the concepts easier to understand.
"""


# ============================================================
# Step 1: Create a Class
# ============================================================

class Work:
    pass


"""
class Work:

- Work is a class.
- A class is a blueprint or template for creating objects.
- In Python, a class is itself an object.
- The type of the Work class is 'type'.

Example:
"""

print(type(Work))

# Output:
# <class 'type'>


"""
Therefore:

Work
  ↓
A class object

Type of Work
  ↓
type


When the class definition is executed, the Work class is created.
However, no instance of Work has been created yet.
"""


# ============================================================
# Step 2: Create a Constructor (__init__)
# ============================================================

class Work:

    def __init__(self, name, age):
        self.name = name
        self.age = age


"""
__init__():

- __init__ is a special method.
- It is normally called when an object is initialized.
- Its main purpose is to initialize the state of an instance.

self:

- self represents the current object/instance.
- self.name and self.age are instance attributes.

Example:

work = Work("John", 30)

Here:

self
 ↓
work object

self.name
 ↓
"John"

self.age
 ↓
30
"""


# ============================================================
# Step 3: Create a Method
# ============================================================

class Work:

    def __init__(self, name, age):
        self.name = name
        self.age = age

    def showInfo(self):
        print(f"Name: {self.name}, Age: {self.age}")


"""
showInfo():

- showInfo is a method of the class.
- Technically, a method is a function defined in a class namespace.
- self is used to access attributes of the current instance.

Example:

work.showInfo()

Conceptually, this can be thought of as:

Work.showInfo(work)

Therefore:

work
 ↓
self

So:

self.name
 ↓
work.name

self.age
 ↓
work.age
"""


# ============================================================
# Step 4: Create an Object
# ============================================================

work = Work("John", 30)


"""
When this statement executes:

work = Work("John", 30)

Conceptually, several things happen:

1. A new Work instance is created.
2. A reference to the new object is obtained.
3. __init__() is called to initialize the instance.
4. Inside __init__():

       self.name = "John"
       self.age = 30

   are assigned.
5. The work variable refers to that object.

Conceptual Diagram:

    Variable / Reference
    -------------------

        work
          |
          |
          v
    +----------------------+
    |   Work Object        |
    |----------------------|
    | name = "John"        |
    | age  = 30            |
    +----------------------+

Python objects are generally allocated in heap-managed memory.

However, saying that "work is definitely stored on the stack"
is not technically guaranteed by the Python language.
"""


# ============================================================
# Step 5: Call the Method
# ============================================================

work.showInfo()


"""
Output:

Name: John, Age: 30


work.showInfo()

Here, the showInfo() method of the work object is called.

Conceptually:

work.showInfo()

can be thought of as:

Work.showInfo(work)

Therefore:

work object
     ↓
    self

Then:

self.name
     ↓
work.name
     ↓
"John"

self.age
     ↓
work.age
     ↓
30
"""


# ============================================================
# Step 6: Create Multiple Objects
# ============================================================

work1 = Work("John", 30)
work2 = Work("Alice", 25)


"""
Two separate Work objects are created here.

Conceptual Diagram:

       work1
         |
         v
   +----------------+
   | Work Object    |
   | name = John    |
   | age  = 30      |
   +----------------+


       work2
         |
         v
   +----------------+
   | Work Object    |
   | name = Alice   |
   | age  = 25      |
   +----------------+


work1 and work2 are two different objects.

Therefore:

work1.name != work2.name
work1.age  != work2.age
"""


# ============================================================
# Step 7: Object Identity using id()
# ============================================================

print("work1 id:", id(work1))
print("work2 id:", id(work2))


"""
id():

id() returns the identity value of an object.

Example:

id(work1)
id(work2)

If the objects are different, they will normally have
different identity values.

Important:
---------

id() should not simply be defined as a "memory address".

In CPython, id() is commonly related to the object's memory
address, but according to Python's language semantics,
id() represents the object's unique identity during its lifetime.

Therefore:

id(work1)

is better described as:

"the identity value of the work1 object"
"""


# ============================================================
# Step 8: Delete a Reference
# ============================================================

del work1


"""
del work1

This removes the name/reference work1 from the namespace.

However, it does not necessarily mean that the object itself
has immediately been deleted.

If another reference to the object exists,
the object can continue to exist.

Example:

work1 = Work("John", 30)

another = work1

del work1

Now:

another
   |
   v
Work Object


Even though work1 has been deleted,
the object still exists because another refers to it.
"""


# ============================================================
# Step 9: Reference Counting and Garbage Collection
# ============================================================

work1 = Work("John", 30)

work1 = None


"""
work1 = None

Now work1 no longer refers to the Work object.

If there are no other references to the object,
CPython may deallocate the object when its reference count
reaches zero.

Python's garbage collector also helps handle cyclic references.

Therefore, it is not always correct to say:

"No reference → Garbage Collector immediately deletes the object"

A better explanation is:

"If an object is no longer reachable, the Python implementation
may eventually reclaim its memory.

In CPython, reference counting often causes many objects
to be deallocated quickly."
"""


# ============================================================
# Complete Example
# ============================================================

class Work:

    def __init__(self, name, age):
        self.name = name
        self.age = age

    def showInfo(self):
        print(f"Name: {self.name}, Age: {self.age}")


# Create objects

work1 = Work("John", 30)
work2 = Work("Alice", 25)


# Call methods

work1.showInfo()

# Object identity

print("work1 id:", id(work1))

# Delete reference

del work1


# Request garbage collection

gc.collect()


# work2 still exists

print("work2 still exists:", id(work2))

# ============================================================
# 3. Instance Method
# ============================================================

"""
An Instance Method is a method that works with the data
of a particular object/instance.

Characteristics:

✔ Usually has self as the first parameter
✔ Can be called through an object
✔ Can access instance variables
✔ Can work with different data for different objects
"""

class Student:

    def __init__(self, name):
        self.name = name

    def show(self):
        print(self.name)


s1 = Student("Faruk")

s1.show()


# ============================================================
# 4. What is self?
# ============================================================

"""
self represents the current object/instance.

self is a conventional parameter name.

When:

s1.show()

is called, it can conceptually be understood as:

Student.show(s1)

Therefore:

s1 → self
"""


# ============================================================
# 5. Instance Method Formula
# ============================================================

"""
Instance Method
       ↓
     self
       ↓
Current Object
       ↓
Instance Data
"""


# ============================================================
# 6. Class Method
# ============================================================

"""
A Class Method is a method that works with class-level
data or class-level behavior.

The @classmethod decorator is used.

Characteristics:

✔ Uses @classmethod
✔ First parameter is conventionally cls
✔ Can access class variables
✔ Can modify class variables
✔ Can be called through the class or an instance
✔ Can be used to create alternative constructors
"""

class Student:

    school = "TMSS"

    @classmethod
    def change_school(cls, name):
        cls.school = name


Student.change_school("ABC School")

print(Student.school)


# ============================================================
# 7. What is cls?
# ============================================================

"""
cls represents the current class.

It is a conventional parameter name.

self → Current Object

cls → Current Class
"""


# ============================================================
# 8. Static Method
# ============================================================

"""
A Static Method is a method where Python does not automatically
pass self or cls.

It is commonly used for utility/helper functionality.

The @staticmethod decorator is used.
"""

class Math:

    @staticmethod
    def add(a, b):
        return a + b


print(Math.add(5, 3))


# ============================================================
# 9. When Should We Use a Static Method?
# ============================================================

"""
Use a static method when:

✔ self is not required
✔ cls is not required
✔ Class state is not required
✔ Instance state is not required
✔ Utility/helper functionality is needed
"""


class Math:

    @staticmethod
    def square(n):
        return n * n


print(Math.square(5))

"""
Method Overloading means using the same method name

For example:

Languages such as Java and C++ support traditional

First add()

# ============================================================
# 26. Method Overriding
# ============================================================

"""
Method Overriding occurs when a child class provides
a new implementation of a method inherited from
a parent class.

Inheritance is required.
"""

class Parent:

    def greet(self, name):
        print("Hello from Parent")


class Child(Parent):

    def greet(self, name):
        print("Hello from Child")


obj1 = Parent()
obj2 = Child()

obj1.greet("John")
obj2.greet("John")


# ============================================================
# 27. Main Conditions for Overriding
# ============================================================

"""
1. Inheritance must exist.
2. The parent class must have the method.
3. The child class defines a method with the same name.
4. The child can provide a new implementation.
5. Calling the method on a child object uses the child's
   implementation.
"""


# ============================================================
# 28. Method Overriding + super()
# ============================================================

class Parent:

    def greet(self, name):
        print("Hello from Parent")


class Child(Parent):

    def greet(self, name):

        super().greet(name)

        print("Hello from Child")


obj = Child()

obj.greet("John")


"""
Output:

Hello from Parent
Hello from Child
"""


# ============================================================
# 29. super()
# ============================================================

"""
super().greet(name)

accesses the next implementation of greet()
according to the method resolution order (MRO).

In this simple example:

Child.greet()
     ↓
super().greet()
     ↓
Parent.greet()
"""


# ============================================================
# 30. Overloading vs Overriding
# ============================================================

"""
| Topic                    | Overloading                    | Overriding                    |
|--------------------------|--------------------------------|-------------------------------|
| Main idea                | Same name + different inputs   | Child redefines parent method |
| Classes                  | Usually same class              | Parent + Child                |
| Inheritance              | Not required                   | Required                      |
| Direct Python support    | Traditional form: No           | Yes                           |
| Purpose                  | Handle different inputs        | Redefine existing behavior    |


Memory:

Overloading
→ Same Class + Different Inputs

Overriding
→ Parent → Child + New Implementation
"""

# ============================================================
# 33. Duck Typing
# ============================================================

"""
Duck Typing is a Python programming style where
the object's behavior or capability is more important
than its actual type.

Main idea:

"If it walks like a duck
and quacks like a duck,
treat it like a duck."

Therefore:

What class is the object?
        ↓
Less important

Can the object provide the required behavior?
        ↓
More important
"""


# ============================================================
# 34. Duck Typing Example
# ============================================================

class Duck:

    def quack(self):
        print("Quack! Quack!")


class Person:

    def quack(self):
        print("I'm quacking like a duck!")


def make_it_quack(thing):
    thing.quack()


make_it_quack(Duck())
make_it_quack(Person())

    def __call__(self, a, b):
        return a + b

    def __call__(self, a, b):
        return a * b


def calculate(operation, a, b):
    return operation(a, b)

print(calculate(Multiply(), 5, 3))

# ============================================================
# Polymorphism with Collections
# ============================================================

"""
Polymorphism with Collections means storing objects of
different classes in the same collection, such as a list,
and using the same method call on every object.

Each object can respond differently to the same method call.

Example:

animals = [Dog(), Cat(), Bird()]

Here:

Dog, Cat, and Bird are different classes.

But all of them provide the same method:

speak()

Therefore:

for animal in animals:
    animal.speak()

The same interface is used for different objects.
"""


# ============================================================
# Abstract Base Class
# ============================================================

from abc import ABC, abstractmethod


class Animal(ABC):

    @abstractmethod
    def speak(self):
        pass


# ============================================================
# Subclasses
# ============================================================

class Dog(Animal):

    def speak(self):
        return "Woof!"


class Cat(Animal):

    def speak(self):
        return "Meow!"


class Bird(Animal):

    def speak(self):
        return "Chirp!"


# ============================================================
# Collection of Objects
# ============================================================

animals = [
    Dog(),
    Cat(),
    Bird()
]


# ============================================================
# Polymorphism in Action
# ============================================================

for animal in animals:
    print(animal.speak())


# ============================================================
# Output
# ============================================================

"""
Woof!
Meow!
Chirp!
"""


# ============================================================
# How It Works
# ============================================================

"""
The collection contains different objects:

animals
   |
   +---- Dog()
   |
   +---- Cat()
   |
   +---- Bird()


Then:

for animal in animals:
    print(animal.speak())


First:

animal = Dog()
animal.speak()
        ↓
"Woof!"


Second:

animal = Cat()
animal.speak()
        ↓
"Meow!"


Third:

animal = Bird()
animal.speak()
        ↓
"Chirp!"
"""


# ============================================================
# Same Interface, Different Behavior
# ============================================================

"""
The method name is the same:

speak()

But the behavior is different:

Dog  → "Woof!"
Cat  → "Meow!"
Bird → "Chirp!"

This is polymorphism.
"""


# ============================================================
# Important Point
# ============================================================

"""
The for loop does not need to know the exact class of the object.

It only expects that the object provides:

speak()

Therefore:

for animal in animals:
    print(animal.speak())

works with Dog, Cat, and Bird.

This demonstrates polymorphic behavior.

It also fits Python's duck-typing style because the code
can rely on the required behavior rather than explicitly
checking the concrete class.
"""


# ============================================================
# Why Use Collections with Polymorphism?
# ============================================================

"""
Polymorphism with collections helps us:

1. Store different types of objects together.
2. Use one common interface.
3. Avoid writing separate code for each class.
4. Make code easier to extend.
5. Reduce unnecessary type-checking logic.
6. Improve flexibility and maintainability.
"""


# ============================================================
# Example Without Polymorphism
# ============================================================

"""
Without polymorphism, we might write:

for animal in animals:

    if isinstance(animal, Dog):
        print(animal.speak())

    elif isinstance(animal, Cat):
        print(animal.speak())

    elif isinstance(animal, Bird):
        print(animal.speak())


This is unnecessary for this example.

With polymorphism, we simply write:
"""

for animal in animals:
    print(animal.speak())


# ============================================================
# Adding a New Class
# ============================================================

class Cow(Animal):

    def speak(self):
        return "Moo!"


# Add Cow to the same collection

animals.append(Cow())


# The same code still works

for animal in animals:
    print(animal.speak())


# Output:

"""
Woof!
Meow!
Chirp!
Moo!
"""


# ============================================================
# Key Point
# ============================================================

"""
We added a completely new class:

Cow

But we did not need to change this code:

for animal in animals:
    print(animal.speak())

This is one of the major benefits of polymorphism.
"""

# ============================================================
```
