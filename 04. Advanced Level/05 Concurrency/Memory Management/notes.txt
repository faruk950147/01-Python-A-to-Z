# 1. Stack

## Stack কী?

**Stack** হলো একটি linear data structure।

এটি **LIFO** নিয়ম অনুসরণ করে।

**LIFO = Last In, First Out**

এর অর্থ:

> Stack-এ সর্বশেষ যে item যোগ করা হয়, সেটিই প্রথমে বের হয়।

### উদাহরণ

ধরা যাক আমরা যোগ করলাম:

```text
Push 10
Push 20
Push 30
```

তাহলে Stack হবে:

```text
[10]
[20]
[30] ← Top
```

যদি আমরা `pop()` করি:

```text
30
```

প্রথমে `30` remove হবে।

কারণ `30` সর্বশেষ যোগ করা হয়েছিল।

---

# 2. Stack Operations

Stack-এর চারটি সাধারণ operation আছে।

### 1. Push

Stack-এর উপরে একটি item যোগ করে।

```text
Push 10
```

### 2. Pop

Stack-এর উপরের item remove করে।

```text
Pop → 30
```

### 3. Peek / Top

উপরের item-টি দেখায়, কিন্তু remove করে না।

### 4. isEmpty

Stack খালি কিনা তা check করে।

---

# 3. Python-এ Stack

Python-এর `list`-কে Stack হিসেবে ব্যবহার করা যায়।

```python
stack = []

stack.append(10)
stack.append(20)
stack.append(30)

print(stack)
```

Output:

```text
[10, 20, 30]
```

এখানে:

```text
append() → Push
pop()    → Pop
```

### Pop Example

```python
last_item = stack.pop()

print(last_item)
print(stack)
```

Output:

```text
30
[10, 20]
```

# 7. Heap

Programming-এ **Heap** শব্দটির দুটি ভিন্ন অর্থ থাকতে পারে।

এখানে প্রথমে আমরা **Heap Data Structure** সম্পর্কে জানব।

Heap হলো একটি **tree-based data structure**।

এটি সাধারণত **Priority Queue** তৈরিতে ব্যবহার করা হয়।

দুটি প্রধান ধরনের Heap আছে:

1. Min Heap
2. Max Heap

---

# 8. Min Heap

**Min Heap**-এ সবচেয়ে ছোট element root-এ থাকে।

উদাহরণ:

```text
       10
      /  \
    20    30
```

এখানে:

```text
10 = smallest element
```

তাই:

```text
Min Heap → সবচেয়ে ছোট element উপরে থাকে
```

---

# 9. Max Heap

**Max Heap**-এ সবচেয়ে বড় element root-এ থাকে।

উদাহরণ:

```text
       30
      /  \
    20    10
```

এখানে:

```text
30 = largest element
```

তাই:

```text
Max Heap → সবচেয়ে বড় element উপরে থাকে
```

---

# 10. Python-এ Heap

Python-এ `heapq` module রয়েছে।

এটি **min-heap** implementation প্রদান করে।

```python
import heapq

heap = []

heapq.heappush(heap, 30)
heapq.heappush(heap, 10)
heapq.heappush(heap, 20)

print(heap)
```

সবচেয়ে ছোট element পাওয়া যাবে:

```python
heap[0]
```

উদাহরণ:

```python
print(heap[0])
```

Output:

```text
10
```

# 11. Heap Operations

### `heappush()`

Heap-এ একটি element যোগ করে।

```python

```

### `heappop()`

সবচেয়ে ছোট element remove করে এবং return করে।

```python
heapq.heappop(heap)
```

### `heap[0]`

সবচেয়ে ছোট element দেখায়, কিন্তু remove করে না।

```python
heap[0]
```

### `heapify()`

একটি সাধারণ list-কে heap-এ convert করে।

```python
numbers = [30, 10, 20, 5, 40]

heapq.heapify(numbers)

print(numbers)
```

গুরুত্বপূর্ণ:

> Heap কোনো **sorted list নয়**।

এটি শুধু heap property অনুসরণ করে।

# 13. Memory

সাধারণ কিছু storage হলো:

```text
RAM
Cache
SSD/HDD
```

### RAM

RAM হলো program চলার সময় ব্যবহৃত প্রধান working memory।

### SSD/HDD

SSD এবং HDD হলো secondary storage।

কম্পিউটার বন্ধ হয়ে গেলেও এগুলো data ধরে রাখে।

# 17. Call Stack

**Call Stack** হলো একটি runtime structure যা function call manage করতে সাহায্য করে।

এটি Python-কে মনে রাখতে সাহায্য করে:

1. কোন function বর্তমানে চলছে
2. কোন function সেটিকে call করেছে
3. Execution কোথায় ফিরে যাবে

Call Stack অনুসরণ করে:

```text
LIFO
```

---

# 18. Stack Frame

প্রতিটি function call একটি **execution frame** তৈরি করে।

একটি frame-এর মধ্যে সেই function call-এর জন্য প্রয়োজনীয় তথ্য থাকে, যেমন:

* Local variables
* Function arguments
* Execution state
* Execution চালিয়ে যাওয়ার প্রয়োজনীয় তথ্য

সহজভাবে:

```text
Function Call
      ↓
New Frame
      ↓
Call Stack
```

---

# 19. Call Stack Example

ধরা যাক:

```python
def func_a():
    print("Inside func_a")
    func_b()
    print("Exiting func_a")


def func_b():
    print("Inside func_b")
    func_c()
    print("Exiting func_b")


def func_c():
    print("Inside func_c")


print("Program started")
func_a()
print("Program ended")
```

Output:

```text
Program started
Inside func_a
Inside func_b
Inside func_c
Exiting func_b
Exiting func_a
Program ended
```

---

# 20. Call Stack Flow

শুরুতে:

```text
[main]
```

যখন `func_a()` call করা হয়:


যখন `func_a()` থেকে `func_b()` call করা হয়:

```text

```

যখন `func_b()` থেকে `func_c()` call করা হয়:

```text

```

যখন `func_c()` শেষ হয়:

```text

[func_b] ← Top
```

যখন `func_b()` শেষ হয়:

```text
[main]
[func_a] ← Top
```

যখন `func_a()` শেষ হয়:

```text
[main] ← Top
```

তারপর program শেষ হয়।

# 22. Recursion

## Recursion কী?

**Recursion** হলো এমন একটি technique যেখানে একটি function নিজেকেই call করে।

উদাহরণ:

```python
def countdown(n):
    if n == 0:
        return

    print(n)
    countdown(n - 1)
```

Call:

```python
countdown(3)
```

Flow:

```text
countdown(3)
      ↓
countdown(2)
      ↓
countdown(1)
      ↓
countdown(0)
```

Base case-এ পৌঁছানোর পর function-গুলো একে একে return করে।

---

# 23. Recursion এবং Call Stack

যখন আমরা call করি:

```python

```

তখন Call Stack:

```text
[countdown(3)]
```

তারপর:

```text
[countdown(3)]
[countdown(2)]
```

তারপর:

```text
[countdown(3)]
[countdown(2)]
[countdown(1)]
```

তারপর:

```text
[countdown(3)]
[countdown(2)]
[countdown(1)]
[countdown(0)]
```

Base case-এর পরে function-গুলো reverse order-এ return করে।

এ কারণেই recursion Call Stack ব্যবহার করে।

# 25. Garbage Collection

## Garbage Collection কী?

```text
Object আর প্রয়োজন নেই
          ↓

          ↓
Memory reclaim করা যেতে পারে
```

# 27. Reference Counting

**Reference Counting** একটি object-এর দিকে কতগুলো reference আছে তা track করে।

উদাহরণ:

```python
a = []
```

Conceptually:

```text
a
│
▼
[]
```

এখন:

```python
b = a
```

Conceptually:

```text
a ──┐
    ├──> []
b ──┘
```

এখন দুটি variable একই object-কে refer করছে।

যদি আমরা করি:

```python
del b
```

তাহলে শুধু `b`-এর reference remove হবে।

`a` এখনও object-টিকে refer করবে।

---

# 28. Reference Count Example

CPython-এ আমরা `sys.getrefcount()` ব্যবহার করে reference count দেখতে পারি:

```python
import sys

a = []

b = a

print(sys.getrefcount(a))

del b

print(sys.getrefcount(a))
```

গুরুত্বপূর্ণ:

```python
sys.getrefcount()
```

নিজেই object-এর জন্য সাময়িকভাবে আরেকটি reference তৈরি করে।

তাই returned number সাধারণত আমরা যে সংখ্যা আশা করি তার চেয়ে **এক বেশি** হতে পারে।

Exact value পরিস্থিতির ওপর পরিবর্তিত হতে পারে।

---

# 29. `del` কী করে?

`del` একটি **name/reference** remove করে।

এটি এমন নয় যে:

> "এখনই Garbage Collection চালাও।"

উদাহরণ:

```python
a = []
b = a

del a
```

Object এখনও আছে কারণ:

```text
b → object
```

অর্থাৎ এখনও একটি reference রয়েছে।

তারপর:

```python
del b
```

দ্বিতীয় reference-টিও remove হয়।

যদি আর কোনো reference না থাকে, তাহলে CPython সাধারণত reference counting-এর মাধ্যমে object-এর memory reclaim করতে পারে।

# 30. Circular Reference

**Circular Reference** তখন হয় যখন object-গুলো একে অপরকে এমনভাবে refer করে যে একটি cycle তৈরি হয়।

উদাহরণ:

```text
A → B
B → A
```

Python example:

```python
class Node:

    def __init__(self):
        self.ref = None


a = Node()
b = Node()

a.ref = b
b.ref = a
```

এখন:

```text
a → b
b → a
```

এটিকে **reference cycle** বলা হয়।

---

# 31. Circular Reference কেন গুরুত্বপূর্ণ?

ধরা যাক আমরা করি:

```python
del a
del b
```

তবুও object-গুলো একে অপরকে reference করতে পারে।

Conceptually:

```text
Object A → Object B
    ↑          ↓
    └──────────┘
```

এখন কোনো external reference নেই, কিন্তু object-গুলো এখনও একে অপরকে refer করছে।

Reference counting একা এই cycle remove করতে পারে না।

**Cyclic Garbage Collector** unreachable cycle খুঁজে বের করে memory reclaim করতে পারে।

---

# 32. Generational Garbage Collection

Python-এর cyclic garbage collector বিভিন্ন generation ব্যবহার করে।

Conceptually:

```text
Generation 0
     ↓
Young objects

Generation 1
     ↓
যেসব object collection থেকে বেঁচে গেছে

Generation 2
     ↓
Long-lived objects
```

মূল ধারণা:

> Young objects দ্রুত garbage হওয়ার সম্ভাবনা বেশি।

তাই younger generation-গুলো বেশি ঘনঘন check করা হয়।


`gc.collect()` garbage collection চালায়।

বিশেষ করে cyclic garbage-এর ক্ষেত্রে নির্দিষ্ট সময়ে collection trigger করতে এটি ব্যবহার করা যেতে পারে।

# 36. Finalization

**Finalization** বলতে বোঝায় object finalization-এর সময় cleanup-related action সম্পন্ন করা।

একটি class-এ define করা যায়:

```python
__del__()
```

উদাহরণ:

```python
class MyClass:

    def __init__(self, name):
        self.name = name

    def __del__(self):
        print(f"{self.name} is being finalized")
```

তারপর:

```python
obj = MyClass("Object1")

del obj
```

Simple CPython case-এ `__del__()` দ্রুত execute হতে পারে।

তবে এর exact timing-এর ওপর **নির্ভর করা উচিত নয়**।

# 37. কেন `__del__()` দিয়ে Resource Cleanup করা উচিত নয়?

গুরুত্বপূর্ণ resource cleanup-এর জন্য সাধারণত:

```python
__del__()
```

ব্যবহার করা উচিত নয়।

যেমন:

* File close করা
* Database connection close করা
* Lock release করা
* Network connection close করা

কেন?

কারণ সাধারণ Python behavior-এ finalization ঠিক কখন হবে তার exact timing guaranteed নয়।

# 38. Context Manager

এটি আরও safe এবং predictable।

# 39. Memory Leak

## Memory Leak কী?

**Memory Leak** হলো এমন একটি পরিস্থিতি যেখানে program এমন memory ধরে রাখে যা আর প্রয়োজন নেই।

Python-এ unnecessary reference object-কে alive রাখতে পারে।

উদাহরণ:

```python
leaky_list = []


def create_data():
    for i in range(10000):
        leaky_list.append("x" * 1000)


create_data()
```

Object-গুলো এখানে থেকে যাবে:

```python
leaky_list
```

যতক্ষণ list-টি থাকবে, ততক্ষণ object-গুলোর reference থাকবে।

এটি **retained memory**-এর একটি উদাহরণ।

বাস্তব memory leak আরও complex হতে পারে।

---

# 40. Memory Leak কমানোর উপায়

কিছু useful practice:

1. অপ্রয়োজনীয় reference remove করুন।
2. অনেক বড় global list avoid করুন।
3. Cache-এর size সীমিত রাখুন।
4. Unused callback/event listener remove করুন।
5. File সঠিকভাবে close করুন।
6. Database connection close করুন।
7. Context manager ব্যবহার করুন।
8. Long-lived object যেগুলো অন্য object-কে reference করে সেগুলো check করুন।

# 47. Memory Flow

একটি সহজ memory flow:

```text
Program starts
      ↓
Function is called
      ↓
Call stack gets a frame
      ↓
Function creates objects
      ↓
Objects use memory
      ↓
References change/remove
      ↓
Object becomes unreachable
      ↓
Reference Counting / Cyclic GC
      ↓
Memory can be reclaimed
```

বাংলায়:

```text
Program শুরু
      ↓
Function call হয়
      ↓
Call Stack-এ Frame যোগ হয়
      ↓
Function Object তৈরি করে
      ↓
Object memory ব্যবহার করে
      ↓
Reference পরিবর্তন/Remove হয়
      ↓
Object unreachable হয়
      ↓
Reference Counting / Cyclic GC
      ↓
Memory reclaim করা যেতে পারে
```

# 48. Complete Call Stack Example

```python
def a():
    print("A start")
    b()
    print("A end")


def b():
    print("B start")
    c()
    print("B end")


def c():
    print("C running")


print("Program started")

a()

print("Program ended")
```

Execution:

```text
Program started
      ↓
     a()
      ↓
     b()
      ↓
     c()
      ↓
c() returns
      ↓
b() returns
      ↓
a() returns
      ↓
Program ended
```

Call Stack:

```text
main
 ↓
a
 ↓
b
 ↓
c
```

তারপর function-গুলো reverse order-এ return করে:

```text
c
 ↓
b
 ↓
a
 ↓
main
```

এটি LIFO behavior।

# 49. Important Exam Points

## Stack

* Linear data structure
* LIFO অনুসরণ করে
* Push একটি item যোগ করে
* Pop একটি item remove করে
* Peek/Top top element দেখায়
* Python `list` Stack হিসেবে ব্যবহার করা যায়

---

## Heap

* Tree-based data structure
* সাধারণত Priority Queue-এর জন্য ব্যবহৃত হয়
* Min Heap → সবচেয়ে ছোট element root-এ
* Max Heap → সবচেয়ে বড় element root-এ
* Python `heapq` min-heap operations প্রদান করে

---

## Call Stack

* Active function call manage করে
* Stack Frame ব্যবহার করে
* LIFO অনুসরণ করে
* Function call → frame যোগ হয়
* Function return → frame remove হয়
* Recursion Call Stack ব্যবহার করে

---

## Memory

* RAM → Primary working memory
* SSD/HDD → Secondary storage
* Python automatically object memory manage করে

---

## Garbage Collection

* Automatic memory-management process
* Unreachable object-এর memory reclaim করতে সাহায্য করে
* CPython Reference Counting ব্যবহার করে
* Cyclic GC unreachable reference cycle handle করে

---

## Reference Counting

* Object-এর reference count করে
* Count zero হলে CPython সাধারণত object reclaim করতে পারে

---

## Circular Reference

* Object-গুলো একে অপরকে reference করে
* উদাহরণ: `A → B` এবং `B → A`
* Reference counting একা unreachable cycle handle করতে পারে না
* Cyclic GC cycle detect এবং collect করতে পারে

---

## Memory Leak

* অপ্রয়োজনীয় memory retained থাকে
* প্রায়ই unwanted reference-এর কারণে হয়
* Long-lived object অন্য object-কে alive রাখতে পারে

---

## Finalization

* `__del__()` object finalization-এর অংশ হতে পারে
* Predictable resource cleanup-এর জন্য এর ওপর নির্ভর করা উচিত নয়
* Context Manager ব্যবহার করা উচিত
